Abstract — 실측 예비 검증

LLM 행동 기반 방어 시스템 초안의 근거를 보완하기 위해, 자체 가상 웹사이트의 방어 구성요소 제거 실험과 행동 규칙의 반례 재생을 수행했다. 실제 HTTP 요청 1,280건은 고정 사례 16개를 8개 방어 조합에서 10회 반복한 것이다. 모든 방어를 적용하면 공격 결과 0/80, 정상 대조 유지 80/80이 관측됐다. XSS는 미인코딩 반사를 검사했으며 브라우저 실행을 측정하지 않았다. 별도 합성 특징 재생에서는 정상 인코딩 변경·권한 오류 반복·공유 IP의 오경보와 IP 회전의 이력 단절을 확인했다. Qwen 등 LLM은 호출하지 않았으며 본 결과는 전체 LBADS나 공개 IDS 데이터셋의 성능 검증이 아니다.

1. 서론 — 예비 검증의 연구 질문

원 초안의 Qwen 기반 행동 분석 설계를 발전시키기 위해 (RQ1) 요청 경로에서 검증된 방어 패치가 공격 결과를 바꾸는가, (RQ2) 차단 피드백의 인과 순서를 요구하면 정상 기법 변경의 오경보를 줄일 수 있는가, (RQ3) IP와 행위자 식별 단위의 차이가 탐지 이력을 어떻게 끊는가를 검토한다.

이번 공헌은 재현 가능한 로컬 예비 실험과 설계 반례이다. LLM의 추가 성능, 공개 데이터셋 우위, 운영 수준 강건성은 향후 검증 대상이다.

2. 관련 연구 — 비교 범위

원문을 확인한 ZERO-APT [2]는 Windows Server 2022 post-exploitation 환경에서의 폐루프 공격자·방어자·판정자 프레임워크이다. Hybrid LLM-IDS [3]는 GPT-2를 결합한 IDS이며, SHIELD [5]는 호스트 로그 기반 분석이다. AMDS [7]는 앙상블 기반 공격 유형별 탐지 전략과 제한된 적응형 white-box 변형을 다룬다. 이 결과를 본 로컬 웹 실험의 직접 비교군 실측치로 합산하지 않는다.

본 예비 검증의 차별점은 공격 성능 우월성의 입증이 아니라, 이전 차단과 기법 변경의 인과 조건 및 식별 단위를 분리해 설계 반례를 재현하고 요청 경로의 실제 방어 패치를 조합별로 확인한다는 데 있다. [1], [6], [8]은 원문 미검증 상태이며 관련 수치를 확정 주장으로 유지하지 않는다.

3. 위협 모델과 평가 범위

HTTP 실험은 소유한 loopback 가상 사이트의 SQL 인젝션, XSS 미인코딩 반사, IDOR만 포함한다. 공격 입력은 고정되어 있으며 LLM이 생성하지 않았다. 행동 실험은 생성기가 제공한 의심 여부·기법·차단 결과·가상 시간·IP·신뢰 세션 특징의 상태 기계 재생이다.

분산 IP는 실제 인터넷 호스트가 아니라 재생 특징이다. 시간 기반 시나리오도 24시간 실운영이 아니다. DoS, 경로 탐색, 무차별 대입의 실제 공격 실험은 포함하지 않는다.

4. 설계 보완안

4.1 저지연 실행 경로와 비동기 분석 경로

현재 구현은 SQL 바인딩·문맥별 출력 인코딩·객체 소유권 검사를 즉시 적용한다. 선택적 LLM은 이후 로그를 분석하는 비동기 경로로 분리하는 설계를 제안한다. 비동기 LLM 자체의 효과는 이번에 구현·측정하지 않았다.

4.2 식별 단위와 위험도

IP 이력과 서버가 검증한 세션 이력을 구분한다. 세션 회전·로그인 전 사용자·NAT의 불확실성을 별도 기록해야 한다. 기존 Risk의 입력 단위가 정해지지 않아 θ=70을 재현할 수 없다. 개선식 Risk=100·Σwᵢzᵢ, zᵢ∈[0,1]는 후속 제안이며 정규화·가중치·임계값을 검증 세트에서 확정해야 한다.

4.3 차단 증거와 기법 변경의 인과 조건

이전 의심 요청의 차단 기록과 현재 의심 요청의 다른 기법을 함께 요구한다. 단순 인코딩 다양성이나 정상 권한 오류 반복만으로 적응형 공격을 단정하지 않는다. 요청 결과는 해당 요청 판단 이후에 이력에 추가한다.

4.4 LLM 역할과 미검증 사항

Qwen 및 실시간 Codex API 호출은 0회이다. 코드·해설은 Codex가 미리 작성했다. 따라서 이번 결과로 Qwen의 추론 지연이나 탐지 향상을 주장하지 않는다. LLM 자체 보고 confidence는 보정 확률이 아니며 후속 검증이 필요하다.

5. 실험 설계 — 실제 실행 환경

5.1 환경

Windows 11, Python 3.13.3 표준 HTTP 서버·SQLite 메모리 DB를 사용했다. 그래프는 matplotlib으로 생성했다. Ubuntu, Docker, Nginx, DVWA 또는 GPU 추론 환경을 이번 결과의 환경으로 기재하지 않는다.

5.2 입력과 반복

HTTP 고정 사례 16개(공격 8·정상 대조 8), 방어 8조합, 10회 반복이다. 행동 재생은 7개 고정 시나리오에 시작 시간만 바꾼 30 seed를 적용했다. 반복을 독립 표본으로 해석하지 않는다. 공개 IDS 데이터셋과 10,000건 자체 데이터셋은 이번에 사용하지 않았다.

5.3 지표

HTTP 공격 결과, 정상 대조 유지, 로컬 응답 p50/p95와 시나리오 단위 후보 경보를 측정했다. ATD는 기법 변경 요청을 1로 세며 미탐 수를 함께 보고한다. 전체 LBADS의 DR/FPR/F1, 운영 처리량과 LLM 지연은 측정하지 않았다.

해석 한계: HTTP는 고정 사례 16개를 8개 방어 구성에서 10회 반복했다. 1,280개의 독립 공격이 아니다. XSS는 미인코딩 태그 반사 지표이며 브라우저 실행 성공률이 아니다. 행동 재생은 7개 고정 특징 시나리오에 시작 시간만 바꾼 30개 seed를 적용한 것이다. 의심 여부와 기법 특징을 이상적으로 공급하므로 완벽한 결과도 현실 탐지 정확도의 증거가 아니다. 이력 없는 의심 특징 비교군도 경보 발생 지표에서 동일한 결과를 내므로, 이 데이터만으로 행동 이력의 추가 탐지 효과를 입증할 수 없다. 해당 비교군은 기법 변경 전에도 경보가 나므로 악성 요청 판별과 적응행위 판별을 분리해야 한다. Qwen, Snort, RF, Docker, NSL-KDD, CSE-CIC-IDS2018은 이번에 실행하지 않았다.

후속 본 실험 계획

현재는 논문 주장의 전제와 방어 패치를 확인한 예비 실험이다. 다음 단계는 아래와 같다.

  1. 고정 재생 공격과 차단 응답에 따라 다음 행동을 바꾸는 정책 공격자를 동일 예산으로 비교한다. 정책은 결정 규칙부터 시작하고, LLM 공격자 여부를 별도 조건으로 둔다. AI가 공격을 생성했다고 가정하지 않는다.
  2. 무상태 정규화 룰, 시간 이력 룰, 증거 기반 이력, 동기 LLM, 비동기 LLM을 같은 요청 로그와 동일 예산으로 비교한다. 현재 미구현 조건을 결과 표에 실측으로 넣지 않는다.
  3. 공격 템플릿·행위자·캠페인 단위로 개발/검증/최종 평가를 분리한다. 별도 작성자가 만든 정상 트래픽과 보류 공격 템플릿을 포함해 데이터 누출을 줄인다.
  4. 정확한 탐지 레이블과 공격 성공 여부를 분리하여 DR/FPR/F1, 미탐 포함 ATD, 시간 지연, 정상 요청 p50/p95/p99, LLM 호출률·타임아웃·큐 대기·토큰 비용·정상 기능 손상을 함께 평가한다. 캠페인 단위 신뢰구간을 사용한다.
  5. 기법 특징 오염, 세션 회전, 동일 IP 다중 사용자, 24시간 경계, 모델 출력 오류, 로그 안의 프롬프트 인젝션을 평가한다. LLM 출력은 검증된 대응 식별자만 허용한다.

8. 결론 — 확인한 범위

세 방어가 모두 적용된 구성에서 고정 공격 사례 8종을 각 10회 반복했을 때 SQL·IDOR 성공 및 XSS 미인코딩 반사는 0/80이었고 정상 대조는 80/80 유지됐다. 이는 교육용 가상 대상의 제한된 예비 검증이며 공격 전체의 차단 성능이 아니다.

행동 규칙 반례는 기법 다양성만으로는 악의적 적응을 구분하기 어렵고 IP만으로는 행위자 이력이 단절될 수 있음을 보여준다. 인과 증거·세션 식별을 보완한 규칙의 이상화된 성공을 현실 성능으로 일반화할 수 없다. LLM 추가 효과와 공개 데이터셋 평가를 수행하기 전에는 기존 예정치 94.2%, 3.8%, 11.3%p, ATD 2.3회를 성과로 주장하지 않는다.

참고문헌 (원 초안 목록 · 부분 확인)

원문과 참고문헌 점검

다운로드 폴더의 원본은 수정하지 않았다. 아래 네 참고문헌의 제목·저자와 초록을 원 출처에서 확인했으나, 초안의 모든 주장과 수치를 검증한 것은 아니다.

  • ZERO-APT: Windows Server 2022 post-exploitation 실험이다. 웹 방어 실험의 직접 비교 수치로 합치면 안 된다.
  • Hybrid LLM-Enhanced IDS: 초록의 6.3% 정확도 개선·9.0% false positive 감소를 확인했으며, 본 환경에서 재현하지 않았다.
  • SHIELD: 호스트 로그 평가이다. LBADS 웹 환경과 평가 단위가 다르다.
  • AMDS: 두 가지 adaptive white-box 변형에 국한된 결과라는 원문의 제한을 함께 적어야 한다.
  • NSL-KDD 공식 안내와 CSE-CIC-IDS2018 공식 안내: 이번에 다운로드·실행하지 않았다. CIC-IDS2018은 네트워크 캡처·시스템 로그·흐름 특징을 제공하므로 실제로 사용할 아티팩트와 파서를 구체적으로 지정해야 한다.
