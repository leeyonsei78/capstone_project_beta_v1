후속 실험 추가: 이력 정보와 LLM 기여 분리 결과로 이동. 아래 SQL 실험은 선행 예비 검증이며 후속 주 실험과 사후 탐색은 문서 뒤에 구분해 추가했습니다.

로컬 SQL 인증 테스트베드에서 LLM 방어 정책 적용 시점의 예비 평가

논문 반영용 실험·결과 보완본 | 2026-11-16 | 원본 논문은 보존. 이 문서는 문헌 검토를 대체하는 최종 투고본이 아니라 실제 측정에 근거한 초록·방법·결과·논의 초안이다.

초록

Docker 없이 Windows 로컬 HTTP 서버와 SQLite를 구성하여 Qwen 기반 SQL 인증 공격·방어의 실행 가능성과 정책 적용 시점을 평가하였다. 수동 AI 공격 캠페인에서는 방어 없음에서 인증 우회가 2/3회 발생했고 고정 규칙과 동기·비동기 AI 방어에서는 관측되지 않았다. 이후 공격 4종과 정상 대조 6종을 동일 순서로 재생하는 5조건·3반복 실험을 수행하였다. 재생 실험의 공격 성공은 방어 없음 12/12, 고정 규칙 3/12, 항상 안전한 구현 0/12, 동기 AI 0/12, 비동기 AI 3/12였다. 이 결과는 사전 적용된 안전한 구현의 효과와 비동기 패치 전 노출 가능성을 보여주지만, AI의 추가 탐지 효과나 운영 환경 성능을 입증하지 않는다. 입력은 의도적으로 구성한 개발 사례이며 독립 보류 평가가 아니다.

1. 연구 질문과 실험 범위

RQ1: 자체 취약 로그인에서 실제 모델이 생성한 입력으로 인증 우회와 방어 적용을 관찰할 수 있는가? RQ2: 동일한 고정 입력에서 규칙 차단·항상 안전한 구현·동기/비동기 정책 선택은 인증 우회와 정상 기능 유지에 어떤 차이를 보이는가? RQ3: 비동기 분석이 완료되기 전 요청이 처리될 때 피해가 발생하는가? AI는 검증된 monitor/parameterize 중 하나를 선택하며 새 방어 코드를 생성하지 않는다.

2. 환경 및 재현 방법

실행 환경: Windows-11-10.0.26200-SP0, Python 3.13.3, Ollama 0.40.16, 모델 qwen2.5-coder:14b. 모든 공격 대상은 127.0.0.1의 캠페인별 임시 포트이며 외부 서버를 사용하지 않았다. HTTP 서버·SQLite는 Python 표준 라이브러리다. Docker/WSL/microVM 격리 성능을 평가하지 않았다.

모델 식별값: 9ec8897f747e246e970bc5cfdda85d22f1123dc2e3d34978a010a75968716849. 양자화: Q4_K_M. 추론 설정: {"num_ctx": 2048, "num_predict": 80, "temperature": 0, "seed": 20261116}. GPU 종류·점유율은 이번 manifest에서 별도 측정하지 않았으므로 과거 GPU 스냅샷을 현재 실측값으로 기재하지 않는다. 모델과 자원을 공유하는 다른 프로세스의 영향을 완전히 배제했다고 주장하지 않는다.

재현 명령: python -m unittest -v → python experiments/run_sql_replay.py --repeats 3 --gap 0.5 → python experiments/build_local_paper.py --run research/replay_runs/<실행ID>. 실행마다 새 디렉터리를 만들며 실행 전 manifest, 소스 사본·해시, 요청/응답, 정책 이벤트, 모델 입출력·토큰·대기·추론 시간을 저장한다. Ollama 호출 실패는 대체 답변 없이 failed로 저장한다. 기존 추론 코드의 타임아웃은 서버 측 생성 취소를 보장하지 않는다.

4. 실험 B: 동일 입력 재생 설계

10개 사례는 공격 4개, 올바른 비밀번호 로그인 4개, 틀린 비밀번호와 없는 계정 각 1개로 구성했다. 정상 계정 O'Reilly와 team--blue 및 규칙이 놓치는 공격 문법은 SQL 문자열 조합과 정규식의 한계를 드러내기 위해 의도적으로 작성했다. 개발 중 테스트를 통해 취약 구현의 공격 성공과 안전 구현의 정상 동작을 확인했다. 규칙에 맞춰 구성한 사례이므로 일반적 공격 분포나 자연 트래픽을 대표하지 않는다.

5조건을 각각 3회 실행했다. 반복마다 입력 순서와 조건 순서를 seed로 섞되 같은 반복의 모든 조건에 동일한 입력 순서를 사용했다. 총 150 HTTP 요청이며 독립 사례 150종이 아니다. 요청마다 같은 초기 DB를 만들고 캠페인마다 방어 상태와 이력을 초기화했다. 응답 후 0.5초 간격의 순차 요청이므로 일정 도착률 부하가 아니며 동기 분석은 다음 요청 시각도 늦춘다. AI 공격자는 사용하지 않고 Qwen 방어자만 호출한다. 두 AI 조건 모두 영구 패치 후에는 추가 분석을 생략한다. 수동 실험과 정책 구현이 달라 별도로 보고한다.

공격 성공은 공격 레이블 요청의 비인가 인증, 정상 기능 유지는 HTTP 200·SQL 오류 없음·기대 인증 사용자 집합 일치로 정의했다. 잘못된 비밀번호 거부와 올바른 비밀번호 인증을 모두 포함한다. 정상 규칙 차단은 정상 레이블의 HTTP 403이며 전체 시스템의 운영 FPR이 아니다. AI의 parameterize는 안전한 구현 선택이므로 그 자체를 악성 판정이나 오탐으로 세지 않는다. 평균·백분위수는 이 개발 입력의 기술 통계이며 신뢰구간이나 유의성 검정을 제시하지 않는다.

6. 논의 및 타당성 위협

첫째, 항상 안전한 구현과 동기 AI 조건이 비슷한 보안 결과를 보이더라도 AI의 필요성이 입증되는 것은 아니다. 동일한 SQL 바인딩을 처음부터 적용하는 비교군은 모델 호출을 요구하지 않는다. AI 정책은 첫 정상 요청에서도 패치를 선택할 수 있으므로 이 결과는 악성 입력 탐지 능력의 증거가 아니다. 본 환경은 정책 선택의 적용 시점을 평가하며 복잡한 대응 선택의 이점은 후속 과제다.

이번 재생 실험에서 첫 정상 요청을 분석한 뒤 parameterize를 선택하고 추가 분석을 하지 않은 AI 캠페인은 6개였다. 해당 동기 캠페인의 좋은 결과는 공격을 식별한 뒤 대응한 결과가 아니라 첫 요청부터 안전한 구현으로 전환한 결과다.

둘째, 단순 규칙의 정상 계정 차단과 공격 누락은 의도적으로 만든 반례다. 이 수치로 상용 WAF나 다른 규칙 기반 시스템보다 우월하다고 주장할 수 없다. 취약 구현의 apostrophe 계정 오류는 정상 기능 결함으로, team--blue의 403은 규칙의 정상 요청 차단으로 구분한다.

셋째, 비동기 정책은 패치 전 노출 구간을 가진다. 수동 AI 공격 실험에서는 공격 생성 시간이 방어에 시간을 제공했지만 고정 재생에서는 더 빠르게 후속 입력이 도착한다. 두 실험의 차이는 공격 생성 유무·요청 순서·정책 호출 규칙·스케줄링이 함께 달라진 결과이므로 비동기 효과의 단일 인과 추정으로 해석하지 않는다. 후속 실험에서 도착률과 초기 안전 정책을 통제해야 한다.

넷째, 사례 작성자와 구현 작성자가 같고 표본은 작으며 모델·프롬프트·seed도 제한적이다. 반복은 실행 순서 변동을 확인할 뿐 독립 공격의 다양성을 늘리지 않는다. SQL 인증만 평가했고 XSS 실행·IDOR·행동 적응 탐지·세션 회전·공개 IDS 데이터·실시간 Codex 방어를 검증하지 않았다. 탐지율 94.2%, FPR 3.8%, 11.3%p 개선, ATD 2.3회 등 원 초안의 예정 수치를 실측 성과로 유지해서는 안 된다.

7. 결론 및 논문 반영 지침

Windows 로컬 환경에서 실제 Qwen 공격 및 정책 선택, HTTP 인증 결과, 정책 적용 시점의 기록을 완료하였다. 동일 입력 재생은 사전 적용한 SQL 바인딩의 효과, 단순 규칙의 제한, 비동기 패치 전 노출을 구분해 관찰할 수 있게 했다. 현재 근거는 소규모 개발 테스트베드의 기능·기전 검증이며 AI 방어의 일반적 우월성을 입증하지 않는다. 독립 작성한 보류 사례, 정상 업무 트래픽, 여러 모델·반복 캠페인, 도착률 통제를 통해 추가 검증해야 한다.

후속 실험: 이력 정보와 LLM 판별 기여의 분리

동결된 주 실험과 사후 탐색 분석을 구분한 논문 반영 자료. 기존 SQL 방어 실험의 결과는 그대로 보존하였다.

1. 연구 질문과 논문 기여

기존 실험에서는 AI가 정상 입력에서도 SQL 바인딩을 켰으므로 탐지 기여를 입증할 수 없었다. 이번에는 SQL 바인딩·출력 인코딩·문서 소유권 검사를 항상 적용하고, 별도의 판별기가 요청 이력에서 거부 이후 기법 변경을 식별하는지 관찰 전용으로 평가했다. 판별 결과를 방어에 적용하지 않았으므로 AI에 의한 피해 예방이나 정상 기능 보호 효과를 측정한 것은 아니다.

본 실험의 기여는 (1) 현재 관찰이 동일한 양성/음성 대조쌍을 통한 이력 정보의 필요성 점검, (2) 단순·강화 이력 규칙과 LLM을 비교하여 이력 효과와 모델 효과 분리, (3) 명확한 사건 순서 기준과 원시 HTTP 기반 판정, (4) 직접 판정의 실패와 기법 추출/시간 규칙 분해의 사후 진단이다. 새로운 알고리즘의 독창성이나 일반적인 IDS 우월성을 주장하지 않는다.

2. 방법과 동결

양성은 실제 거부(401/403)를 받은 SQL 또는 타인 문서 탐색 이후 다른 기법의 의심 요청이 나타나는 에피소드다. 양성 스크립트는 실제 거부 응답을 받은 경우에만 후속 탐색을 전송한다. 음성은 정상 활동과 비적응 공격으로 나누며, false 판정은 무해하다는 의미가 아니다. 다른 기법 요청이 최초 거부보다 먼저 나타난 순서 반전 대조도 포함한다. 공격은 고정 분기 스크립트이며 LLM이 생성하거나 학습한 정책은 아니다.

6개 설계 가족 × 2변형 × 양성/음성 = 24개 에피소드, 12대조쌍이다. 양성 12개, 정상 음성 6개, 비적응 공격 음성 6개다. 각 에피소드의 3요청으로 관찰 HTTP 72건을 만들고 별도 정상 로그인·본인 문서 대조 48건을 실행했다. 총 120 HTTP 요청이다. 변형 중 동일한 전체 관찰도 있어 고유 전체 이력은 21개다. 이 수치를 독립 시나리오 24종 또는 120종으로 해석하지 않는다.

모든 에피소드의 마지막 요청/응답은 동일하다. 같은 입력에 같은 결정을 내리는 현재 요청 전용 판별기는 이 균형 대조쌍에서 정확도 50%를 넘을 수 없다. 이는 설계상 정보 제약으로, 실제 운영 데이터에서 현재 요청 기반 탐지가 50%에 불과하다는 뜻이 아니다. 이력이 필요한 과제라는 사실과 LLM이 이력을 활용하는 능력은 별개다.

원시 요청/상태/응답만 판별기에 전달하고 정답·ID·시나리오명·작성 의도·이상화된 기법 특징은 제외했다. 단순 규칙은 제한된 SQL/HTML 패턴과 문서 403을, 강화 규칙은 괄호형 OR·iframe 등의 추가 패턴을 사용한다. 두 이력 규칙은 실제 관찰에서 특징을 추출한 뒤 거부→다른 기법 조건을 검사한다. 강화 규칙도 동일 작성자가 이 개발 과제에 맞춰 작성했으며 상용 WAF를 대표하지 않는다.

모델 qwen2.5-coder:14b, Ollama 0.40.16, Python 3.13.3, Windows-11-10.0.26200-SP0. 옵션은 {"num_ctx": 4096, "num_predict": 64, "temperature": 0, "seed": 20261117}. 추론 전에 코드·프롬프트·정답·관찰·호출 순서를 동결했고 결과를 보고 주 실험을 재조정하지 않았다. 독립 작성자가 만든 블라인드 보류 평가나 외부 사전 등록은 아니다. 모델 워밍업 1회는 평가에서 제외하고 무작위 순서로 48회 호출했다. 판정은 에피소드 종료 후 1회이므로 온라인 탐지 지연은 측정하지 않았다.

5. 사후 탐색: 기법 추출과 시간 규칙 분리

주 실험 결과를 확인한 뒤 추가한 탐색이다. 같은 관찰을 재사용했으므로 독립 확인 실험으로 볼 수 없다. Qwen은 단일 요청의 기법을 none/sql/html/document 중 하나로 분류하고, 명시적 코드가 관측된 거부 이후 다른 기법이 나타났는지 판단했다. 정답 대신 실제 모델의 추출값을 사용했다. 이 실험은 프롬프트·출력 형식·과제 분해를 함께 바꾸므로 개선 원인을 시간 추론 한 가지로 단정할 수 없다.

6. 논문에 넣을 해석과 한계

본 실험에서는 이력 정보의 유무와 이를 처리하는 판별기의 능력을 분리하였다. 마지막 관찰이 동일한 대조쌍에서 이력은 판별에 필요한 정보를 제공했으나, 단일 LLM의 직접 판정은 강화된 명시적 규칙에 미치지 못했다. 이 결과는 LLM에 전체 로그를 제공하는 것만으로 피드백 이후의 기법 변경을 안정적으로 식별할 수 있다는 가정을 지지하지 않는다. 구조화된 기법 추출과 명시적 시간 규칙을 결합하는 접근은 사후 탐색으로 평가했으며 독립 평가가 필요하다.

한계: 6개 의도적 가족과 종속·중복 변형, 현재 관찰을 같게 만든 인위적 과제, 작성자 공유, 단일 모델·프롬프트·seed, 제한된 SQL/HTML/문서 시나리오, 고정 student 세션, 판별기 관찰 전용이다. 판단 기준은 관측된 사건 관계이지 공격자의 의도나 학습을 증명하는 기준이 아니다. 세션 회전·공유 IP·다중 사용자·실제 네트워크 공격 분포·운영 false positive rate를 평가하지 않았다.

논문에서는 기존 SQL 결과를 구현 검증으로 유지하고, 이 대조쌍 실험을 이력/모델 기여 분리 실험으로 추가한다. 사후 탐색은 별도 절에 배치한다. 현재 결과를 AI 방어 성능 향상으로 포장하지 않고, 안전한 기본 방어·관측 근거·명시적 시간 규칙의 역할과 LLM의 실패 범위를 밝히는 근거로 사용한다.

7. 다음 확인 실험

독립 작성한 새 시나리오에서 기존 규칙·프롬프트를 고정해 직접 판정과 구조화된 분해를 비교해야 한다. 현재와 같은 대조쌍 외에 마지막 요청 자체에도 판별 정보가 있는 자연스러운 흐름, 정상 보안 문서 검색, 혼합 사용자 이력, 긴 이력과 무관한 요청, 입력 변형을 포함한다. 모델/프롬프트/seed와 캐시 조건을 통제하고, 충분한 독립 가족을 확보한 뒤 캠페인 또는 가족 단위의 불확실성을 평가한다. 모델 선택을 결과를 본 뒤 바꾸면 탐색 단계임을 명시한다.
