2. Docker Desktop 설치

Docker Desktop Windows 공식 설치 페이지에서 PC 아키텍처에 맞는 설치 파일을 받습니다. 일반적인 Intel·AMD PC는 x86_64입니다.

설치 후 Docker Desktop을 실행하고 다음을 확인하세요.

- Linux 컨테이너 사용
- Settings → General에서 WSL2 엔진 사용
- Settings → Resources → WSL Integration에서 Ubuntu 연동 활성화

설정 항목은 설치 버전에 따라 조금 다를 수 있습니다. 새 PowerShell 창에서 아래를 실행합니다.

docker version에 Client와 Server 정보가 모두 나오고, hello-world가 정상 출력되면 기본 준비가 끝난 것입니다. 최초 실행은 이미지를 내려받기 위해 인터넷을 사용합니다. 공격 실험의 외부 통신 차단은 이후 실험 네트워크에 별도로 적용합니다.

3. microVM용 KVM 사용 가능 여부 확인

microVM은 제품명이 아니라 경량 가상머신 방식입니다. 이번에는 Firecracker를 후보로 사용하겠습니다. Firecracker는 Linux와 읽기·쓰기가 가능한 /dev/kvm을 필요로 하므로 Windows에 실행 파일만 설치해서는 동작하지 않습니다. Firecracker 공식 시작 안내

Ubuntu 터미널에서 실행하세요.

uname -m
uname -r
ls -l /dev/kvm
test -r /dev/kvm && test -w /dev/kvm && echo "KVM READY" || echo "KVM NOT READY"

결과에 따라 다음처럼 진행합니다.

| 결과 | 다음 단계 |
|---|---|
| KVM READY | Firecracker 설치·게스트 부팅 확인으로 진행 |
| /dev/kvm은 있지만 접근 불가 | KVM 그룹·장치 권한 확인 |
| /dev/kvm 자체가 없음 | 중첩 가상화와 커널 지원 확인, 필요하면 별도 Linux 환경 사용 |

WSL2에는 nestedVirtualization 설정이 있지만, 설정 하나만으로 모든 PC에서 Firecracker 실행이 보장되는 것은 아닙니다. /dev/kvm과 실제 게스트 부팅으로 확인해야 합니다. Microsoft WSL 설정 문서

KVM이 안 되면 논문 본 실험에는 별도 Ubuntu PC 또는 KVM 중첩 가상화를 지원하는 Linux VM을 권합니다. Docker 실험은 먼저 진행할 수 있습니다.

4. Firecracker 준비

KVM 확인 후 Firecracker 공식 Releases에서 Linux 아키텍처에 맞는 안정 버전과 함께 제공되는 jailer를 받습니다. 논문 재현성을 위해 선택한 버전과 파일 체크섬을 기록합니다.

준비할 구성품은 다음과 같습니다.

- firecracker: microVM 실행기
- jailer: 실행기의 권한·환경 격리
- 해당 버전에 맞는 Linux 게스트 커널
- 실험용 root filesystem 이미지

공식 시작 안내는 기본 부팅 예제이며 jailer를 생략합니다. 우리 공격 실험에는 별도의 격리 설정과 외부 통신 차단 검증을 추가한 뒤 사용하겠습니다. 처음에는 공격 코드 없이 게스트 부팅·종료만 확인합니다.

5. 설치 후 실험 구성

Docker와 microVM은 두 개의 실행 조건으로 비교하겠습니다.

- Docker 조건: 내부 네트워크의 취약 사이트와 제한된 HTTP 실행기
- microVM 조건: 별도 게스트 커널 안에서 같은 실험 수행
- 공통 조건: 동일한 입력·판정 기준·자원 예산과 감사 로그

Qwen 추론은 실행 샌드박스 밖에 두고, 검증된 요청·응답만 전달하도록 구성할 예정입니다. Docker나 microVM 설치가 현재 Ollama 자원 경합을 자동으로 해결하지는 않으므로, 모델 실험 시간도 별도로 확보해야 합니다.

우선 1~3단계를 완료한 뒤 docker version, docker compose version, wsl --list --verbose, /dev/kvm 확인 결과를 보내 주세요. 그 결과에 맞춰 Firecracker 부팅과 실제 실험 패키지 구성을 이어가겠습니다.

먼저 Windows를 재부팅하면 됩니다. 로그상 WSL 설치는 완료됐지만, Ubuntu는 아직 설치되지 않았습니다. 그래서 WSL_E_DISTRO_NOT_FOUND가 발생한 것입니다.

1. 진행 중인 작업을 저장하고 Windows를 다시 시작하세요. 실행 중인 논문 실험이 있다면 종료될 수 있으니 완료 여부를 먼저 확인하세요. WSL 구성 요소를 적용하려면 재부팅이 필요합니다. Microsoft 설치 안내
2. 재부팅 후 관리자 PowerShell에서 실행하세요.

   wsl --install -d Ubuntu-24.04
3. Ubuntu 설치 후 Linux 사용자 이름과 비밀번호를 만드세요. 비밀번호를 입력할 때 화면에 글자가 표시되지 않는 것은 정상입니다. Ubuntu 창이 자동으로 열리지 않으면 다음을 실행하세요.

   wsl -d Ubuntu-24.04
4. Ubuntu에서 exit를 입력해 PowerShell로 돌아온 뒤 확인하세요.

   wsl --list --verbose

   아래처럼 VERSION이 2이면 준비된 것입니다. Stopped 또는 Running은 둘 다 괜찮습니다.

     NAME             STATE           VERSION
* Ubuntu-24.04     Stopped         2

새로 설치한 배포판은 기본적으로 WSL 2를 사용하므로, 지금은 wsl --set-version을 다시 실행할 필요가 없습니다. 공식 설명

설치가 완료되면 wsl --list --verbose 결과를 보내주세요. 이어서 Docker 설치와 microVM 실행에 필요한 KVM 지원 여부를 확인하겠습니다.
