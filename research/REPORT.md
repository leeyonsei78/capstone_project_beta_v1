# 로컬 SQL 인증 테스트베드에서 LLM 방어 정책 적용 시점의 예비 평가

논문 반영용 실험·결과 보완본 | 2026-11-16 | 원본 논문은 보존. 이 문서는 문헌 검토를 대체하는 최종 투고본이 아니라 실제 측정에 근거한 초록·방법·결과·논의 초안이다.

## 초록

Docker 없이 Windows 로컬 HTTP 서버와 SQLite를 구성하여 Qwen 기반 SQL 인증 공격·방어의 실행 가능성과 정책 적용 시점을 평가하였다. 수동 AI 공격 캠페인에서는 방어 없음에서 인증 우회가 2/3회 발생했고 고정 규칙과 동기·비동기 AI 방어에서는 관측되지 않았다. 이후 공격 4종과 정상 대조 6종을 동일 순서로 재생하는 5조건·3반복 실험을 수행하였다. 재생 실험의 공격 성공은 방어 없음 12/12, 고정 규칙 3/12, 항상 안전한 구현 0/12, 동기 AI 0/12, 비동기 AI 3/12였다. 이 결과는 사전 적용된 안전한 구현의 효과와 비동기 패치 전 노출 가능성을 보여주지만, AI의 추가 탐지 효과나 운영 환경 성능을 입증하지 않는다. 입력은 의도적으로 구성한 개발 사례이며 독립 보류 평가가 아니다.

## 1. 연구 질문과 실험 범위

RQ1: 자체 취약 로그인에서 실제 모델이 생성한 입력으로 인증 우회와 방어 적용을 관찰할 수 있는가? RQ2: 동일한 고정 입력에서 규칙 차단·항상 안전한 구현·동기/비동기 정책 선택은 인증 우회와 정상 기능 유지에 어떤 차이를 보이는가? RQ3: 비동기 분석이 완료되기 전 요청이 처리될 때 피해가 발생하는가? AI는 검증된 monitor/parameterize 중 하나를 선택하며 새 방어 코드를 생성하지 않는다.
