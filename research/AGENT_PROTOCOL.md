# 자율 공격 에이전트 실험 설계 (Cochise + AutoPenBench)

Status: draft, not yet implemented. Docker is not installed on this machine yet (as of 2026-11-17);
this document can be reviewed and revised before Docker setup, and implementation starts after.

## 왜 이 조합인가 (대체 결정 근거)

ARTEX(jiwoochris/artex-global 및 포크)는 검토 후 기각하였다. 정찰부터 데이터 탈취까지 수행 가능한
범용 침투 도구이고, 실제 악용 의혹이 보도된 바 있으며, 명령 샌드박싱이 README에 명확히 설명되어
있지 않다. 대신 아래 두 공개 연구 도구를 쓴다.

- **Cochise** (Happe & Cito, TU Wien, arXiv:2605.11671 / ASE '26, MIT 코드 라이선스,
  https://github.com/andreashappe/cochise): 플래너-익스큐터 2단계 구조의 630줄 레퍼런스 구현체.
  논문이 스스로 "최첨단 공격 도구가 아니라 모델·구조 비교용 재사용 가능한 실험 인프라"라고 명시한다.
  신뢰된 실행 호스트(Kali VM)에서 SSH로 격리된 테스트베드만 공격하는 구조로 설계되어 있다.
- **AutoPenBench** (Gioacchini 외, arXiv:2410.03225, MIT 라이선스,
  https://github.com/lucagioacchini/auto-pen-bench): 33개 과제(인비트로 22 + 실제 CVE 11),
  명령/단계 마일스톤 기반 평가. 공개된 기준치: 완전 자율 에이전트 21% 성공률, 사람 보조 64%.

이 조합의 장점: 둘 다 공개·재현 가능하고, SSH로 격리된 표적만 공격하는 동일한 구조라 서로 맞물린다.
ARTEX와 달리 "범용 임의 침투"가 아니라 "미리 정한 33개 과제 중 하나를 공격"하는 좁은 범위다.

**정정(2026-11-17):** Cochise의 익스큐터는 매 단계 LLM이 명령을 자유롭게 생성하므로, "자율성 수준"
자체는 ARTEX와 다르지 않거나 더 즉흥적이다. Cochise를 고른 근거는 자율성이 낮다는 것이 아니라
(1) 공격 범위가 설계상 신뢰된 점프 호스트에서 닿는 격리 테스트베드로 한정됨 (2) 630줄로 감사 가능함
(3) 악용 보고가 없음(증거 없음일 뿐, 안전 증명은 아님)이다. 자율성이 높을 때의 실제 위험은 이슈 #13
(아래)이 보여준다 — **안전은 에이전트의 자율성이 아니라 저희가 만드는 네트워크 격리에서 나온다.**
어떤 에이전트를 쓰든 격리는 선택이 아니라 필수 전제다.

## 확인해야 할 사항 (구현 전)

1. **GitHub 이슈 #13 (Cochise)**: SSH 호스트 키 검증 비활성화, SSH 응답 미정제, LLM 명령 미검증 실행.
   프롬프트 인젝션으로 2차 명령 실행이 가능하다는 미해결 이슈(2026-08-04, 미확인 claim). 설치 전

   위험이 있는지 판단한다. 표적이 공격자를 역공격하는 시나리오는 이 연구에서 쓰지 않을 계획이지만,
   표적 응답에 우연히 인젝션 문자열이 섞이는 경우까지는 점검한다.
2. **라이선스**: 둘 다 MIT. 코드 재배포·수정 가능.
3. AutoPenBench의 "EMNLP 2025 Industry Track" 게재 주장은 미확인(아카이브 Comments 란에 게재 표시 없음).
   인용 시 "arXiv:2410.03225 (게재 학회 미확인)"으로 표기한다.

## 채택된 핵심 기여 (2026-11-17 확정)

**"Cochise의 비정형 Knowledge 컴포넌트를 networkx 기반 정식 그래프(탐색 그래프 + 자산 그래프,
앵커 연결)로 교체하고, 멀티타겟 환경에서 성능을 실측 비교한다."**

근거 및 범위 한정:
- Cochise는 이미 PTT(작업 계획, 마크다운 트리)와 Knowledge(자격증명·엔티티 추적)를 분리해 관리한다.
  따라서 "단일 구조에 이중 그래프를 처음 도입"한다는 주장은 사실과 다르므로 쓰지 않는다.
- 실제 변경 지점은 `knowledge.py`의 비정형 추적을, ARTEX식 정식 그래프(networkx: 탐색 그래프 =
  태스크/의도/발견, 자산 그래프 = 호스트/포트/취약점/계정, 두 그래프를 앵커로 연결)로 교체하는 것이다.
- 비교 변수: 멀티타겟(표적 2개 이상) 환경에서 기존 Knowledge vs 그래프 Knowledge의 성능 차이.
- 성능 향상 수치는 실측 전 논문에 쓰지 않는다. 측정 후 신뢰구간과 함께 보고한다.

## 공격자·방어자 모델 티어 (하이브리드, 2026-11-17 확정)

로컬 양자화 모델만으로는 실제 위협(호스팅 프런티어 모델을 쓰는 공격자)을 과소평가할 수 있다.
반대로 API만 쓰면 재현성이 약해진다. 따라서 **로컬 + API 병행(하이브리드)**으로 간다.

| 역할 | 티어 | 비고 |
|---|---|---|
| 공격자 | 로컬(Qwen/DeepSeek Q4) → DeepSeek API → Claude API | 능력 티어를 L1~L3 사다리와 결합 |
| 방어자 | 로컬 유지(실시간·지연 서사) + API 비교군 | 상한 성능은 API로 확인 |

핵심: 공격자 능력 티어(양자화 로컬 → 호스팅 프런티어)에 따라 방어 효과가 어떻게 변하는지를
능력 사다리와 함께 측정한다. 이것이 로컬-only/ API-only보다 강한 기여다(RQ1/RQ2에 직접 답).

안전·비용·사생활 조건 (필수):
1. 격리와 API 분리 — 에이전트 "두뇌"(추론)만 API로 나가고, "손"(공격 명령/트래픽)은 격리 Docker 안에만.
2. API 키는 환경변수로만(DEEPSEEK_API_KEY, ANTHROPIC_API_KEY). 코드·로그·아티팩트에 기록 금지.
3. 토큰/요청/금액 상한을 코드로 강제. DeepSeek 저렴, Claude 고가.
4. 프롬프트에 합성 데이터만. 사용자 개인정보(이메일 등) 절대 미포함.
5. 호스팅 모델은 호출 시각·버전 스냅샷 명시, 로컬 결과와 나란히 보고.

진행 순서: ① 교차 모델(로컬) 마무리 → ② Docker 격리 구축 → ③ DeepSeek API 공격자 추가(OpenAI 호환) →
④ 결과 보고 → ⑤ Claude 공격자는 비용 승인 후 추가.

```
Docker 네트워크 A (internal: true, 외부 인터넷 차단)

  │     └─ Cochise 에이전트 프로세스 (플래너: LLM 호출, 익스처: SSH 명령)
  └─ 표적 컨테이너(들) ── AutoPenBench 과제 중 선택한 것 (예: in-vitro 웹 보안 5~7개부터 시작)
        └─ 저희의 방어 계측 지점 (6.9/6.10절 ATO 방어를 웹 요청 단위로 재구성하거나,
           별도로 "요청 로그를 보고 suspect/confirmed를 매기는 라우터"를 앞에 둠)

호스트 PC (Ollama)
  └─ Docker 컨테이너에서 host.docker.internal:11434 로 호출 (Qwen/DeepSeek 방어 LLM, Cochise의 플래너 LLM)
```

## 실행 계획 (단계적으로, 매번 변경 요인 하나씩)

1. **0단계 — 격리 검증**: Cochise를 네트워크 A에 올리고, 네트워크 A 바깥(예: 호스트 인터넷)으로 나가는
   요청이 전부 차단되는지 먼저 확인한다. 실험을 시작하기 전에 통과해야 하는 선행 조건이다.
2. **1단계 — 공격만 (방어 없음)**: AutoPenBench in-vitro 과제 3~5개에 Cochise를 그대로 돌려 베이스라인
   성공률을 측정한다. 공개된 벤치마크 수치(21%)와 비교해 저희 환경 구성이 맞는지 검증한다.
3. **2단계 — 차단형 방어 추가**: 요청 로그 기반 규칙(페이로드 서명, 반복 실패)으로 의심/확정 시 연결 종료.
4. **3단계 — 기만형(shadow) 방어 추가**: 확정 시 그림자 컨테이너로 전환. 6.10절의 가정이었던 미끼 접촉률을
   여기서 실측한다(공격자가 가짜 엔드포인트/시크릿을 몇 번 건드리는지 실제로 센다).
5. **4단계 — LLM 실시간 판단 방어**: 규칙 대신 Qwen/DeepSeek가 매 요청 risk를 판단. 6.9절 사다리와 같은 축
   (none/rules/llm_sync/llm_escalate)으로 비교한다.

각 단계는 과제 3~5개 × 5~10반복 정도의 소규모로 먼저 돌리고, 패턴이 보이면 표본을 늘린다.

## 공격 에이전트 구조 2종 비교 (고정 파이프라인 vs Cochise의 유연한 ReAct)

Cochise 논문은 스스로 "모델·에이전트 구조를 비교하기 위한 인프라"라고 밝혔다. 이를 살려,
Cochise(유연한 ReAct) 외에 **고정 4단계 파이프라인 에이전트**를 하나 더 만들어 구조 자체를
비교 변수로 둔다.

```
자율 에이전트 (Python, 고정 파이프라인)
│
├── 1. 정찰(Recon): Nmap 자동 실행 → 열린 포트/서비스 파싱       [LLM 미개입]
├── 2. 스캐닝: 서비스 버전 → 후보 취약점/모듈 매칭               [LLM이 후보 중 하나 선택]
├── 3. 익스플로잇: Metasploit(msfrpc) 연동 → 선택 모듈 실행,     [LLM이 모듈 옵션만 채움]
│                  셸 획득 시도
└── 4. 보고: JSON 로그 + 성공률 자동 기록                        [LLM 미개입]
```

Cochise(유연한 ReAct, 매 단계를 LLM이 자유 선택)와 이 고정 파이프라인(단계는 고정, LLM은
제한된 선택지 안에서만 결정)을 같은 표적에 번갈아 돌려, "에이전트 구조가 방어 효과 평가에
영향을 주는가"를 비교 변수로 추가한다.

### 안전 제약 (이 구조에서 특히 중요)
- **Metasploit 모듈 화이트리스트.** LLM이 전체 모듈 카탈로그를 자유롭게 고르지 못하게 하고,
  AutoPenBench 과제의 알려진 서비스 버전에 맞는 모듈만 코드 레벨에서 미리 목록화한다.
- **Nmap 스캔 대상 IP도 코드에서 격리 네트워크 내부로 고정**한다(LLM 입력으로 대상 IP를
  받지 않는다).
- **msfrpc 데몬도 격리 네트워크 안에만 열어 둔다.**
- 지표에 "몇 단계에서 막혔는가"(정찰/스캐닝/익스플로잇 중 어디)를 추가해, 방어가 더 이른
  단계에서 작동하는지 구분한다.

### 구현 메모 (Docker 설치 후 작업)
- Nmap 결과 파싱: `python-nmap` 또는 `subprocess` + XML 출력.
- Metasploit 연동: `msfrpc` 데몬에 붙는 파이썬 클라이언트(RPC)로 모듈 실행·결과 수집.
- 둘 다 Cochise가 이미 쓰는 Kali 실행 호스트 컨테이너에 기본 설치되어 있어 별도 이미지가
  필요 없다.

## 하지 않을 것

- ARTEX, 또는 "범용 침투"를 표방하는 다른 프레임워크 도입
- 네트워크 A 바깥으로 나가는 경로를 만드는 것
- Cochise/공격 표적에 실제 비밀값이나 개인정보를 넣는 것 (전부 합성 데이터)
