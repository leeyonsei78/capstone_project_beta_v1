# 실험의 학술적 의미와 SCIE 투고 가능성 검토

검토 기준일: 2026-11-17. 작업 폴더에 보존된 결과·실행 코드와 공개 저널 정보를 검토했다. 새로운 공격 실험이나 모델 추론은 수행하지 않았다. 원본 실험 결과는 변경하지 않았다.

**종합 판단: 연구로 발전시킬 만한 관찰은 있지만, 현재 자료를 그대로 묶은 SCIE 투고는 권하지 않는다.** 가장 설득력 있는 방향은 LLM의 일반적 우월성 주장이 아니라, 관찰 정보·판정 방식·정책 권한·실행 지연이 방어 결과에 미치는 영향을 분리한 실증 연구다. 평가 지표 수정, 새로운 독립 평가 자료, 강한 비교군, 외부 환경 검증을 보완하면 SCIE 저널을 목표로 삼을 수 있다. 이는 원고 채택 확률 추정이나 게재 보장이 아니다.

**통계 재검산**

`recalculate.py`는 저장된 예측을 짝지어 재집계한다. 결과와 입력 해시는 `review_metrics.json`에 있다. 기존 점수 정의를 그대로 재현한 사후 진단이며, 정답 정의가 타당하다는 인증은 아니다.

| 비교 | 분석 단위와 정답 기준 | LLM / 비교군 정답 | 양측 exact McNemar p |
|---|---|---|---|
| LLM 대 rules | 보류 이벤트 33건 | 31 / 30 | 1.000 |
| LLM 대 rules2 | 보류 이벤트 33건 | 31 / 27 | 0.21875 |
| LLM 대 rules | 보류 사례 23개, 사례 내 모든 이벤트 정답 | 21 / 20 | 1.000 |
| LLM 대 rules2 | 같은 사례 단위 | 21 / 18 | 0.375 |

이벤트는 같은 사례 안에서 의존하므로 이벤트 단위 p값을 본문 확증 검정으로 쓰지 않는 것이 좋다. 사례 단위 분석도 의도적으로 작성한 작은 합성 자료라는 한계를 제거하지 못한다. 다중 비교를 보정하지 않은 탐색 분석이며, 현재 비교에서 LLM 정확도의 유의한 우월성은 관찰되지 않는다. 유의하지 않다는 사실은 동등성 입증이 아니다. 정상 사용자 마찰의 유의성이나 다른 모든 결과의 유의성까지 검정한 것은 아니다.

에이전트 로그는 `ts`, `session` 두 필드만 제외하고 비교했다. fixed, react-flat, react-graph 각각 6회 중 고유 HTTP 궤적이 1개다. 이 반복은 해당 설정의 재현성을 보여주지만 과제 다양성이나 독립 공격 6종을 의미하지 않는다. 이 데이터에 요청 단위 t검정 등으로 표본 수를 부풀려서는 안 된다.

요약의 신뢰구간은 구현상 **Wilson 구간**이다. 일부 계획 문서의 Clopper–Pearson 표현과 일치시키려면 문구 또는 계산을 정리해야 한다. 예를 들어 6/6의 Wilson 95% 하한은 약 61%, 0/6의 상한은 약 39%다. 이것조차 독립 시행이라는 해석 조건이 있어, 동일한 결정적 궤적을 반복한 결과를 현실 모집단 성공률로 일반화해서는 안 된다.

**투고 전에 우선 수정할 문제**

1. **정답 단위가 섞여 있다.** `impossible_travel_takeover`의 설명에는 첫 KR 로그인이 정상이고 이후 CN 로그인이 공격이라고 명시되어 있다. 그러나 사례 전체의 `label=attack`, `allowed=[challenge, lock]`을 첫 이벤트에도 적용한다. 정상 첫 로그인을 allow하면 공격 누락으로 집계된다. 이벤트별 행위자·악성 여부·허용 조치를 별도로 정의하고, 공격 성공은 실제 비인가 행위 또는 보호 자산 접근으로 측정해야 한다. 기존 정확도·누락 수치는 현재 채점기의 수치로만 제시한다.

2. **한 번 탐지한 것과 탈취를 예방한 것은 다르다.** `ato_stateful.score_case_level()`은 공격 사례 중 challenge/lock이 한 번이라도 있으면 caught로 센다. 위 사례는 세 규칙 모두 `[allow, lock]`인데 caught로 집계된다. 이 경우 첫 allow는 정상일 수 있으므로 곧바로 탈취라고 단정할 수도 없다. 문제는 이벤트 정답과 성공 시점이 정의되지 않아 어느 쪽도 일관되게 측정하지 못한다는 점이다. 정상 clean도 'lock 없음'이라는 뜻이며 추가 인증 마찰 0을 뜻하지 않는다.

3. **보류 자료의 재사용을 독립 검증이라고 부르면 안 된다.** 초기 holdout은 별도 문맥의 AI 작성자가 규칙을 보지 않고 만든 23개 사례이며, 이는 개발자 자체 작성보다 나은 통제다. 그러나 그 결과를 보고 만든 rules3/stateful을 같은 자료에 적용한 것은 사후 개발 평가다. `ato_stateful.py`와 실행기의 'holdout numbers remain independent' 취지의 주석은 수정해야 한다. 기존 자료는 validation으로 전환하고 새 test set을 봉인한다.

4. **현재 stateful 비교는 이력의 추가 효과를 보여주지 못한다.** 최신 사례별 표에서 rules3_stateless와 rules_stateful은 dev와 holdout 모두 같은 결과다. 이력이 효과적이라고 주장하려면 현재 이벤트가 유사하지만 과거가 다른 새로운 사례, 사건 간 시간 정보, 정상 여행·계정 복구 등 대조군이 필요하다.

5. **그래프 효과와 프롬프트 도움을 분리해야 한다.** `GraphKnowledge.render()`는 `PIVOT AVAILABLE`, 아직 소유하지 않은 호스트, 목표 상태를 명시한다. flat은 사실 목록을 제공한다. 관찰 입력은 같아도 모델에 제시하는 정보 선택과 다음 단계 강조가 다르다. 평균 10→6 요청은 이 구현 묶음의 관찰 차이이며 '그래프 자료구조 자체가 40% 효율 향상'의 증거로 부족하다. 동일 정보의 flat, 정리된 flat, 그래프 요약에서 pivot 안내 제거 등 ablation이 필요하다.

6. **공격 능력과 방어 효과의 범위를 제한해야 한다.** ReAct 프롬프트는 취약 호스트와 이동 경로를 미리 알려준다. `sqli_login`은 주입처럼 보이는 모델 출력을 정해진 성공 페이로드로 바꾼다. 따라서 범용 취약점 발견·익스플로잇 생성 성능이 아니다. `run_agent_arch.py`는 모든 공격 실행 후 로그를 판별하므로, 규칙 탐지 6/6은 공격 차단 6/6을 의미하지 않는다.

7. **판별기에 제공되는 정보를 명시해야 한다.** 규칙은 `sqli_suspected`, `lure`, `honeytoken_used` 등 계측 필드를 사용하고, LLM에는 축약된 경로·상태·일부 태그를 제공한다. `_compact()`는 host와 원시 SQL, honeytoken 사용 여부 등 일부 정보를 제거한다. 결과는 이 정보 제공 방식에도 의존한다. 동등 관측 비교와 원시 로그/축약 로그 ablation을 추가해야 한다. 특정 필드 누락이 이번 0/6의 원인이라고 확정한 것은 아니다.

8. **교차 모델 실험의 혼입과 실행 버전을 정리해야 한다.** 두 교차 방향만으로 Qwen과 DeepSeek 방어자를 순위화하면 공격자 차이가 섞인다. 같은 저장 공격 입력에 방어자만 교체하는 비교와, 별도의 적응형 공격자×방어자 조합 비교가 필요하다. 두 완료 디렉터리는 설정·소스 해시가 같지만 수치가 일부 다르다. 유리한 결과만 채택하지 말고 두 실행을 공개하고 seed·실행 상태·공유 자원 조건을 확인해야 한다. 두 실행을 자동으로 독립 표본 12개로 합치지는 않는다.

9. **재현성 기록을 보강해야 한다.** 에이전트 실행기는 반환 trace를 제거하며, 이번 폴더에 HTTP requests는 있지만 모델의 전체 단계별 prompt/response 아티팩트는 없다. manifest의 source_sha256도 빈 객체다. 소스 사본은 있으므로 일부 추적은 가능하지만, 모델 digest·옵션·단계별 입력/출력·실패·성공 판정·토큰·시간을 보존해야 한다. 이번 검토에서 관련 현재 코드 4개는 최신 실행의 소스 사본과 일치함을 확인했다.

**출판 가치와 선행 연구 대비 위치**

실험 코드, 원시 HTTP 기록, 모델 호출 기록, 강한 규칙 비교를 보유했고 불리한 결과도 남겨둔 점은 장점이다. 특히 'LLM이 덜 잠그지만 더 허용할 수 있다', '비동기 판단 전 손실', '직접 판단과 구조화 추출의 차이'는 하나의 방어 정책 연구로 연결할 수 있다.

그러나 LLM 공격 에이전트를 만들었다는 사실 자체는 충분한 새로움이 아니다. AutoPenBench는 33개 과제의 평가 틀을, Cybench는 40개 CTF 과제를, Cochise는 에이전트 구조 비교용 참조 실행 틀을 제시한다. 현재 자작 과제에서 나온 수치를 이 벤치마크의 성공률과 직접 비교할 수는 없다. [AutoPenBench](https://arxiv.org/abs/2410.03225), [Cybench](https://arxiv.org/abs/2408.08926), [Cochise](https://arxiv.org/abs/2605.11671).

LLM 방어의 실패 자체도 이미 연구되고 있다. 2026년 Cyber Defense Benchmark는 실제 공격 절차 기반의 로그 탐색에서 모델들의 한계를 보고한다. 따라서 'LLM이 보안 로그 판정을 잘 못한다'보다 **동일 관찰에서 정책 완화 권한과 구조화된 판정이 피해·사용자 마찰을 어떻게 바꾸는가**를 구체적인 기여로 제안한다. 이 비교는 관련 연구의 초록·공개 설명에 기초한 예비 검토이며 완전한 신규성 조사나 체계적 문헌 고찰은 아니다. [Cyber Defense Benchmark](https://arxiv.org/abs/2604.19533).

권장 주제: **「LLM 기반 계정 보호에서 정책 권한과 관찰 정보가 보안–사용자 마찰에 미치는 영향」**.

권장 연구 질문은 (a) LLM 단독 판정과 규칙의 최소 방어 수준을 유지하는 결합의 피해 차이, (b) 같은 정보에서 직접 판정·구조화 추출·강한 규칙의 차이, (c) 동기·비동기 적용에서 도착률과 지연에 따른 피해 차이다. SQL은 동기 부여 또는 부록, 에이전트 그래프 비교는 후속 과제로 두는 구성이 현재로서는 가장 집중도가 높다. 그래프를 주제로 선택한다면 별도의 다중 과제·동등 정보 비교가 먼저 필요하다.

**현실적인 추가 실험 순서**

| 우선순위 | 작업 | 완료 판단 |
|---|---|---|
| 1 | 이벤트 정답, 실제 탈취/예방, 정상 마찰, 실패 처리 규정 정리 | 정상 선행 이벤트가 공격 누락으로 잡히지 않고, 사후 탐지가 예방으로 잡히지 않음 |
| 2 | 규칙·프롬프트·정책을 고정하고 새로운 시험 사례 마련 | 기존 holdout과 다른 시나리오 가족, 작성·검수 기록, 시험 이후 수정 금지 |
| 3 | 강한 규칙과 동등 정보 비교 | rules3 등 강화 기준선, LLM 단독·결합, 직접 판정·추출 비교 |
| 4 | 외부 테스트베드/자료 추가 | 논문 주제에 맞는 공개 과제 또는 독립 구현 환경에서 핵심 결과 재현 |
| 5 | 모델·과제·seed 축 확장 | 같은 공격 입력의 방어자 교체 및 적응형 조합 실험을 구분 |
| 6 | 효과크기·불확실성·실행비용 보고 | 사례/과제 군집을 반영한 분석, 실패 포함 분모, 보안·마찰·지연을 함께 보고 |

계획 출발점으로 새 합성 사례 100–200개, 다수의 시나리오 가족, 실제 환경 과제 5–10개부터 실행 가능성을 점검할 수 있다. 이는 저널 요구 표본 수나 충분성 보장이 아니다. 본 실험 규모는 목표 효과크기·허용 오탐 상한·군집 구조에 대한 검정력 또는 정밀도 설계로 정해야 한다. 동일 과제의 반복을 늘리는 것만으로 이 목표를 충족하지 않는다. 정상 오탐률이 매우 낮다는 주장을 하려면 훨씬 많은 독립 정상 사례가 필요할 수 있다.

Docker 도입 자체가 논문 기여를 높이지는 않는다. 중요한 것은 실제 서비스에 가까운 평가, 실행 상태 초기화, 격리와 재현성이다. 실제 외부 서비스를 공격할 필요는 없다.

**투고 후보와 SCIE 확인**

아래 순위는 주제 적합성과 필요한 보완 정도에 대한 검토 의견이다. 채택 확률이나 저널의 공식 난이도 등급이 아니다. 등재 정보는 2026-11-17 웹 확인 기준이며 투고 직전 ISSN으로 다시 확인한다. JIF 또는 Scopus 등재만으로 SCIE라고 판정하지 않았다.

| 후보 | 등재 확인 근거 | 이 연구와의 적합성 | 권고 |
|---|---|---|---|
| IEEE Access | Clarivate MJL 검색 결과에 Science Citation Index Expanded 명시 | 응용 실험, 측정 방법, 부정적 결과를 다루는 범위와 잘 맞음 | 평가 오류 수정·새 시험 자료·외부 검증 후 우선 고려 |
| International Journal of Information Security | Springer 공식 저널 페이지의 Abstracted and indexed in에 SCIE 명시 | 인증·접근통제·시스템 보안, LLM 방어 정책 평가와 직접 관련 | 정책 설계의 기여와 엄밀한 비교를 보강한 뒤 고려 |
| Computers & Security | 해당 저널의 2026년 출판 논문에서 SCIE 수록 명시. 이번 도구에서는 공식 소개 페이지 403, MJL의 해당 ISSN 실시간 상세 조회 실패 | 실용 보안 관점에서 주제 적합성 높음 | 외적 타당성과 선행 연구 대비 기여를 더 크게 보강할 도전 후보. 투고 직전 MJL 직접 재확인 |
| Journal of Computer Virology and Hacking Techniques | Springer 공식 페이지는 Emerging Sources Citation Index 명시 | 공격/방어 실험 주제는 적합 | SCIE 필수라면 제외. ESCI 대안으로만 고려 |

IEEE Access의 SCIE 근거는 [Clarivate MJL 검색 결과](https://mjl.clarivate.com/search-results?issn=IEEE+Access)다. 이 조회는 검색 색인에 저널의 SCIE 항목이 노출되지만 직접 페이지 열기에서는 동적 본문이 반환되지 않았다. 공식 저널은 응용 실험·부정적 결과를 범위에 포함하지만, 실험과 통계의 기술적 수준 및 데이터로 지지되는 결론을 요구한다. 따라서 '부정적 결과라서 쉽게 게재'라고 해석하지 않는다. 완전 공개접근이며 APC가 있다. [공식 범위](https://ieeeaccess.ieee.org/about/), [원고 기준](https://ieeeaccess.ieee.org/authors/preparing-your-article/).

International Journal of Information Security는 공식 페이지에서 SCIE 및 완전 공개접근을 확인했다. 현재 AI·사이버보안 특별 컬렉션이 실험 연구와 LLM 공격/방어를 모집하며 마감은 **2027-01-31**이다. 주제는 맞지만 특별호도 실험 보완을 대체하지 않는다. [저널·등재 정보](https://link.springer.com/journal/10207), [컬렉션 공고](https://link.springer.com/collections/iedbiijhbd).

Computers & Security의 수록 근거는 [동 저널의 2026년 서지 연구](https://www.sciencedirect.com/science/article/pii/S0167404826002361)다. MJL 직접 확인과 동등한 수준의 실시간 등재 조회를 완료했다고 주장하지 않는다. Journal of Computer Virology and Hacking Techniques의 ESCI 표기는 [Springer 공식 저널 페이지](https://link.springer.com/journal/11416)에서 확인했다.
