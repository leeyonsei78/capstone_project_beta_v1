# 피드백 이후 기법 변경 판별: 대조쌍 진단 실험

## 연구 질문과 기여 범위

안전한 기본 구현 위에서, 관측된 거부 이후 다른 탐색 기법으로 바뀌었는지를 판별한다. 과거 실험은 AI가 첫 정상 요청에서도 SQL 바인딩을 켜므로 탐지 기여를 분리하지 못했다. 이번에는 방어를 항상 켜고 판별기를 관찰 전용으로 비교한다. 예방 성능이나 정상 차단 부작용을 AI 결과로 주장하지 않는다.

가설 H1: 현재 요청만 보는 판별보다 전체 이력을 보는 판별이 이 대조쌍 과제에서 더 높은 정확도를 보인다. H2: Qwen 이력 판별이 단순 이력 규칙보다 높은 재현율을 보일 수 있으나 강화된 규칙 대비 추가 이점은 미확정이다. H3: 사건 순서가 바뀐 대조쌍에서 같은 이벤트 집합만으로 판별하면 오류가 발생한다. 결과가 가설에 반해도 모두 보고한다.

## 레이블과 생성

양성: 같은 가상 student 세션에서 SQL 주입 또는 타인 문서 탐색이 실제 HTTP 401/403을 받은 후, 다른 기법(SQL/HTML 삽입/타인 문서)의 의심 요청이 이어진다. 스크립트는 실제 거부 응답을 받은 경우에만 두 번째 단계를 전송한다. AI가 생성하거나 학습한 공격 정책이 아니라 고정된 피드백 분기 스크립트다. 악의적 의도나 심리적 인과를 추정하지 않는다.

음성은 정상 활동과 비적응 공격(동일 기법 반복 또는 다른 기법이 최초 거부보다 먼저 나타난 경우)을 구분한다. 이 과제의 false는 무해하다는 뜻이 아니다. 모든 요청은 HTTP로 수행한다. SQL은 매개변수 바인딩, 검색은 HTML 인코딩, 문서는 서버가 정한 student의 소유권 검사로 보호한다. 가상 세션 토큰은 고정이며 실서비스 인증·세션 강건성을 평가하지 않는다. XSS는 문자열이 인코딩되었는지만 확인하며 브라우저 실행 성공률을 측정하지 않는다.

6개 설계 가족 × 2개 문법/계정 변형 × 양성/음성 = 24 에피소드, 12 대조쌍. 양성 12, 정상 음성 6, 비적응 공격 음성 6이다. 각 에피소드 3요청 중 마지막 요청/응답이 짝에서 정확히 같다. 72개 관찰 요청과 별도 정상 로그인·본인 문서 대조 48개, 총 120 HTTP 요청이다.

현재 요청만으로는 짝을 구분할 수 없다. 동일 입력에 동일 결정을 내리는 판별기의 대조쌍 정확도 상한은 50%다. 이는 설계에 따른 정보 제약이며 AI의 지능 부족 또는 실제 운영 탐지 정확도를 의미하지 않는다. 마지막 요청만 보는 조건과 전체 이력 조건은 정보를 달리 주는 제거 실험이다.

## 비교군

1. rules_current: 현재 요청의 단순 의심 패턴을 사용한 비교군. 기법 변경 판별에 정보가 부족하다.
2. rules_history: 같은 단순 패턴을 HTTP 이력의 거부→다른 기법 조건과 결합.
3. rules_extended: 괄호형 OR 및 iframe 등 인식 범위를 넓힌 이력 규칙. 상용 WAF를 대표하지 않는다.
4. llm_current: Qwen에 마지막 관찰만 제공.
5. llm_history: 같은 Qwen/지시문/옵션에 전체 3관찰 제공.

Qwen에는 정답·시나리오명·pair ID·작성 의도·이상화된 기법 특징을 주지 않는다. 실제 요청 내용과 상태/응답을 제공한다. 강화 규칙도 같은 관찰에서 특징을 추출한다. 401/403만으로 정상 비밀번호 실수를 SQL 공격으로 취급하지 않는다. 정상 검색어에 포함된 기술 단어는 실제 실행 경로에 따라 판단한다.

## 동결과 실행

단위 테스트 후 prepare 단계에서 코드·프롬프트·정답·순서·모델 식별값·HTTP 관찰을 저장/해시 검증하고, 그 뒤 모델 추론을 시작한다. 같은 작성자가 입력과 규칙/프롬프트를 설계했으므로 독립 블라인드 보류 평가가 아니다. 이번 추론 결과를 보고 프롬프트/규칙을 수정해 같은 평가를 다시 좋은 결과로 대체하지 않는다. 수정이 필요하면 새로운 버전으로 표기하고 기존 결과를 보존한다.

모델 qwen2.5-coder:14b, temperature=0, seed=20261117, context=4096, output=64. 별도 일반 JSON 워밍업 1회 후 평가 48회 호출. 입력을 기반으로 응답을 재사용하지 않는다. 조건/시나리오 호출 순서는 seed로 섞는다. 모델 로딩·프롬프트 평가·생성 시간/토큰과 전체 호출 시간을 원문과 함께 보관한다. 캐시와 외부 자원 경쟁은 완전히 통제하지 못한다. 실패는 prediction=null로 두며 음성으로 대체하지 않는다. 연속 3회 모델 실패 시 남은 요청을 미실행으로 보고한다.

## 평가

주 지표는 에피소드 단위 정확도, 양성 재현율, 전체 음성 false-adaptation 비율, 정상만의 오경보율, 비적응 공격의 오귀속률, 양쪽 모두 맞춘 대조쌍 수다. 분모/실패/미실행을 함께 공개한다. 신뢰구간/유의성은 6개 의도적 가족의 종속 변형에 일반화하지 않는다. 모델은 에피소드 끝에서 한 번 판정하므로 온라인 탐지 지연·방어 적용 지연을 측정한 것으로 표현하지 않는다.

중요 한계: 의도적으로 이력이 필요한 과제, 작은 합성 대조쌍, 동일 작성자, 단일 모델/seed, 제한된 서버와 세션. 규칙보다 좋은 결과가 나와도 전반적인 IDS 성능이나 새로운 알고리즘의 우월성을 입증하지 않는다. 이력 효과와 LLM 효과를 분리한 대조 실험 및 실패 사례 분석으로 논문 근거를 보완한다.
