# SQL 동일 입력 재생 예비 실험 계획

2026-11-16 작성. 기존 수동 AI 캠페인을 관찰한 후 설계한 후속 개발용 실험이다. 사전 등록 또는 독립 보류 평가로 표현하지 않는다.

## 범위와 조건

Windows/Python 표준 HTTP 서버와 요청별 SQLite 메모리 DB, 가상 계정만 사용한다. 캠페인마다 별도 loopback 임시 포트와 새 방어 상태·모델 대화 이력을 만든다. 기존 8765/8766 서버를 수정하거나 재시작하지 않는다.

방어 없음, 정규식 규칙, 처음부터 매개변수 바인딩, 동기 Qwen 정책 선택, 비동기 Qwen 정책 선택의 5조건을 비교한다. 공격 입력은 고정하며 AI 공격자를 호출하지 않는다. AI는 monitor/parameterize 중 하나만 선택한다. 두 AI 조건 모두 영구 패치 적용 후에는 추가 분석을 생략한다. 이는 과거 수동 실험의 동기 정책(매번 분석)과 다른 구현이므로 시간 수치를 직접 합치지 않는다. 정상 입력에 대한 parameterize 결정은 차단이나 공격 탐지 판정과 같지 않다.

10개 개발 사례: 공격 4개, 올바른 비밀번호 로그인 4개, 잘못된 비밀번호 및 없는 계정 각 1개. O'Reilly와 team--blue는 SQL 구문 처리와 단순 규칙의 정상 기능 손상을 드러내기 위해 의도적으로 만든 계정이다. 공격도 규칙이 인식하거나 놓치는 문법을 포함하도록 작성했다. 자연 트래픽 빈도나 실제 운영 오탐률을 대표하지 않는다. 테스트에서 취약 구현의 공격 성공 및 안전 구현의 기대 동작을 먼저 검증한다.

기본 3회 반복 × 5조건 × 10요청 = 150 HTTP 요청. 10개 사례를 반복한 것으로 독립 사례 150종이 아니다. seed 20261116으로 반복마다 사례 순서와 조건 순서를 섞고, 같은 반복에서는 모든 조건이 동일 사례 순서를 사용한다. 응답 완료 후 다음 요청 전 0.5초를 기다리는 순차 부하이므로 고정 도착률 부하가 아니다. 동기 판단은 다음 요청 시각도 늦춘다. 비동기 결과는 이 순서·간격·스케줄링에 의존한다.

## 평가와 보존

- 공격 성공: 공격 레이블 요청에서 하나 이상의 가상 계정 인증. HTTP 200 자체는 성공이 아니다.
- 정상 유지: HTTP 200, SQL 오류 없음, 인증 사용자 집합이 사전 정의된 기대값과 정확히 일치.
- 정상 규칙 차단: 정상 레이블 요청의 HTTP 403. 탐지기 전체의 FPR로 표기하지 않는다.
- 패치 전 성공, 캠페인 시작부터 패치 적용까지 시간, HTTP 시간, 판단 시작부터 응답까지 시간, 전체 캠페인 시간, 모델 호출·토큰·대기·추론 시간 기록.
- 모델 실패는 failed 캠페인으로 별도 기록한다. 미실행 요청을 성공적인 방어로 세지 않는다. 요약 시 completed와 failed를 분리한다.
- 매번 새 타임스탬프 디렉터리에 실행 전 manifest(사례/순서/모델 식별값/버전/옵션/소스 해시), 소스 사본, 캠페인 원시 JSON, CSV를 저장한다.
- temperature=0, 모델 seed는 고정. 반복은 실행 변동 확인용이며 통계적 유의성·모집단 신뢰구간을 산출하지 않는다.
- 동일 GPU/Ollama를 사용하며 타 작업과 겹치지 않도록 실행한다. 외부 프로세스의 자원 경쟁을 완전히 통제했다고 주장하지 않는다.
